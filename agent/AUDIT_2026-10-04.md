## C. How to make the coding agent produce better UI + working features

1. **Vertical-slice tasks, not layer tasks.** One task = "user can do X end to end" (route + BFF + hook + UI + test). The current phases built layers (BFF first, UI later) and never proved the loop.
2. **Mandatory UI walk with evidence** in the DoD (Playwright or screenshots at 1280px and 390px, light + dark). Add Playwright now (not Phase 7) with one smoke test per flow: sign-in -> create project -> new chat in project -> send -> title appears.
3. **Contract tests against the real backend**, and a "capability gate" step: before building UI, grep the backend docs; if the capability is missing, write a backend request and build an honest empty/"not available yet" state.
4. **Honest status vocabulary**: `[DONE]` only with live evidence; otherwise `[PARTIAL]` + blocker. Keep a **Known issues** list at the top of current_status.
5. **Don't ask what you can derive** (chat title, default models, project from route, last-used settings). Add this as a design rule in the structure graph.
6. **Context via URL**: project-scoped routes carry `projectId`; create/list calls take the scope from the route, not from user input.
7. **UX checklist in every UI task**: mobile nav, empty/loading/error/pending states, keyboard (Enter/Shift+Enter/IME/Escape), focus management, no hard-coded `vh` heights, optimistic update where safe, toast only on errors you can't show inline.
8. **Design system upgrades** the agent can do next: an `AppPage`/`PageHeader` primitive, a responsive `SplitPane` (sidebar becomes a drawer), a `useResumablePoll` hook for pending server work, a `Tabs` primitive for project pages (Overview/Members/Chats/Knowledge), command palette (Ctrl+K) for chats/projects, message actions (copy/regenerate/branch) inline.
9. **Backend-first for model answers**: until provider adapters exist, add a "dev echo" adapter in the backend (completes responses with a canned answer after 1-2 s) so the whole chat loop can be tested live. Then add real adapters (OpenAI/Anthropic/…) behind the registry's `base_url`.
10. **Keep prompts small and current**: archive finished-phase detail, cap `current_status.txt` at ~150 lines, add a CI check that `package.json` scripts point at existing files.
